## 2. CSCV Mechanics & Combinatorics Verification

### 2.1. Partition Construction

Given a return matrix $M \in \mathbb{R}^{T \times N}$, where $T$ is the number of return periods and $N$ is the candidate model count:
1. $T$ is divided into an even number of contiguous chronological blocks $S$.
2. In the audit configuration, $S = 10$.
3. All combinations of size $S/2 = 5$ are selected to form the training set $J$.
4. The complementary subset $J^c = \{0, 1, \dots, S-1\} \setminus J$ forms the testing set.
5. Total distinct partitions evaluated:
   $$C = \binom{S}{S/2} = \binom{10}{5} = \frac{10!}{5! \cdot 5!} = 252$$

### 2.2. Ranking & Overfitting Definition

For each partition $c \in \{1, \dots, C\}$:
1. Identify the optimal in-sample strategy:
   $$n^*_c = \arg\max_{n=1,\dots,N} R_{IS}(n, c)$$
2. Compute the out-of-sample performance rank of $n^*_c$ relative to all $N$ models:
   $$\bar{r}_c = \frac{\text{Rank}_{OOS}(n^*_c)}{N + 1} \in (0, 1)$$
3. The logits $\lambda_c = \ln\left(\frac{\bar{r}_c}{1 - \bar{r}_c}\right)$ measure relative out-of-sample degradation.
4. Overfitting occurs when the in-sample winner performs below median out-of-sample ($\bar{r}_c \le 0.5$, or $\lambda_c \le 0$).
5. The Probability of Backtest Overfitting (PBO) is defined as:
   $$\text{PBO} = \frac{1}{C} \sum_{c=1}^C \mathbb{I}(\bar{r}_c \le 0.5)$$

## 4. Methodological Limitations & Identified Risks

1. **Gaussian Perturbation Candidates:**
   - As in the DSR module, candidate strategy returns in `run_quant_validation_lab.py` were generated by adding Gaussian noise to the base strategy returns rather than using distinct parameter variations.
   - *Impact:* Because candidates were perturbed copies of an already unprofitable base strategy, the CSCV correctly identified that picking the "best" noisy variant was pure selection noise. The 80.2% PBO is an accurate reflection of noise-fitting.
2. **Lack of Inter-Block Purging & Embargo:**
   - The contiguous blocks are partitioned without buffer gaps (purging) at block borders. If a multi-hour trade spans across a block boundary, return information can theoretically leak between complementary slices.
   - *Severity:* Low in this specific run due to hourly bar sizing and average trade duration, but must be hardened in Phase 3.
